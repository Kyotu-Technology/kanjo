# Feature status

This page says how far the current tree covers the functional specification Kanjo was built from.
Kanjo is an independent open-source project published by Kyotu, not a product of Anthropic. "Claude" and "Claude Code" are Anthropic's names for its products.

## How the statuses were set

The starting point was a coverage matrix written during an internal review, before the review's findings were fixed. Each row was then checked again against the code as it is now. Where a remark says something was run or checked, it was done for this document on Linux with a release build of `kanjo` made from the final tree of this release, in temporary directories with `KANJO_NO_KEYRING=1`: `kanjo demo` and its API, the reports (`daily`, `weekly`, `monthly`, `session`), `kanjo status` and `kanjo blocks --breakdown` on demo-seeded data, `kanjo open` with a stub browser opener, import and rescan of the synthetic transcript fixtures, `kanjo doctor`, backup, restore, purge, retention, `kanjo audit verify`, the statusline command and the egress test. Time zone handling across a daylight saving change was not run; it rests on the code and its tests. None of these checks ran on macOS or Windows or against a real service manager ([status.md](status.md) says what has been checked on each platform), and the web UI was not rendered for this page, so what a remark says about the UI is read from its code. The release workflow ran later, for v0.1.0; rows 10 and 11 say what that run covered.

"done" means the feature exists as the specification describes it for one developer; the remark gives limits that remain. "partial" means part of it is missing. The table lists the specification's features that exist, fully or in part.
