# Kanjo web UI

The dashboard that ships inside the `kanjo` binary. It is a Svelte 5 single-page app (runes, TypeScript) built with Vite into `web/dist`, which the Rust server embeds. Routing is hash based (`#/usage`, `#/sessions/<id>`) and every asset and API URL is relative, so the same build works behind any base path and inside a desktop webview. Nothing is loaded from the network except the Kanjo server itself: no CDN, no remote fonts (the type is the system UI stack), no analytics.

## Working on it

Run `npm ci` once, then `npm run dev` and open `http://localhost:5173/?mock`. The `mock` query parameter (or `VITE_MOCK=1` at build or dev time) swaps the HTTP API for an in-browser implementation over a synthetic dataset, so the UI runs without a server. `?mock=<scenario>` picks a state: `default`, `onboarding`, `empty`, `import`, `nostatusline`, `unpriced` or `unauthorized`. `?lang=en|pl` and `?theme=light|dark` override the saved preferences for one load, and `?step=N` opens the onboarding wizard at a given step, which is handy for screenshots. The gate before handing anything over is `npm run build`, `npm run check` (svelte-check and tsc, zero errors and zero warnings) and `npm test` (vitest).

## Where things live

Design tokens are CSS custom properties in `src/lib/styles/tokens.css`: colour (light values on `:root`, dark values as their own selected steps under `[data-theme='dark']`), the type scale (`--fs-*`), spacing (`--sp-1` to `--sp-10`, a 4 px grid), radius, elevation and the chart palette (`--series-1..6`, `--series-other`, the sequential ramp `--seq-0..6`, `--grid`, `--axis`). Never write a raw colour in a component; reach for a token. The theme store resolves "system" to light or dark and sets `data-theme` on `<html>`, and an inline script in `index.html` does the same before first paint. Status colours (`--good`, `--warning`, `--serious`, `--critical` and their `-ink` and `-soft` variants) mean state only and always come with an icon and a word.

Components are in `src/lib/ui`. The ones you will use most are `Card`, `PageHeader` (title, lede and the single filter row of a page), `Money`, `ConfidenceBadge`, `Stat`, `LimitMeter`, `DataTable` (sortable, with a `cell` snippet), `Tabs`, `Select`, `DateRangePicker`, `Button`, `Dialog`, `Banner`, `EmptyState`, `Skeleton`, `InlineHelp`, `Switch` and `Severity`; toasts go through `toasts.push()` from `src/lib/stores/toast.svelte.ts`. One rule is enforced by types: `Money` requires a `confidence` prop, because every money figure in Kanjo states whether it is official, an estimate or a lower bound. In dense tables pass `badge="none"` and put a compact `ConfidenceBadge` in the column header instead (see `DataTable`'s `header` snippet on a column).

Charts are hand-drawn SVG components in `src/lib/charts`: `StackedBars` (also used for single-series columns), `LineArea`, `Sparkline`, `HourHeatmap`, `CalendarHeatmap` and `ShareBars`. Wrap a chart in `ChartCard`, which adds the legend and the switch to a table view; every chart must have that table twin. Model colours follow the model, never its rank: `modelColor()` and `modelSeries()` in `series.ts` give Opus, Sonnet and Haiku fixed slots, give other models the next free slot and fold the tail into "Other". The categorical palette was checked with the dataviz validator against both surfaces; if you change surfaces or slots, run it again.

Text lives in `src/lib/i18n`. `en.ts` is the source dictionary and `pl.ts` is typed against it, so a missing Polish key fails `npm run check`, and `i18n.test.ts` fails on missing or extra keys, mismatched placeholders, missing Polish plural forms, empty strings and long dashes. Use `t('key', params)` for text, `tn('key', count)` for plurals (forms come from `Intl.PluralRules`; Polish needs `one`, `few` and `many`), and `tk()` only for keys built at run time. Numbers, dates and money go through `fmt` (`fmt.money`, `fmt.pct`, `fmt.when`, `fmt.ago`, `fmt.duration` and friends), which uses `Intl` and the user's `Settings.currency` code and manual `usd_rate`. Sentences that mention a weekday use `fmt.when`, which takes the phrase from the dictionary because Polish needs the preposition and case ("we wtorek", "w środę").

The data layer is in `src/lib/api` and `src/lib/stores`. API types come from `src/lib/api/contract.ts`, a barrel over the bindings generated from `crates/kanjo-core/src/api.rs` (do not edit `bindings/`). `ApiClient` in `client.ts` covers every endpoint in `docs/api.md`, sends `X-Kanjo-CSRF: 1` on mutations and throws `ApiRequestError` with a typed `code`; a 401 switches the app to the "open Kanjo from your terminal" screen. Reads go through the stale-while-revalidate cache in `cache.ts`: in a component call `useQuery(() => queries.usage(params))` from `query.svelte.ts` and read `data`, `loading`, `refreshing` and `error`. The options function is reactive, so a key built from component state refetches when that state changes, and the previous data stays on screen (dimmed through `Card`'s `refreshing` prop) instead of flashing a skeleton. Each query builder in `queries.ts` carries tags; the live connection in `live.ts` listens to `/api/v1/events`, reconnects with exponential backoff and invalidates the tags an event touches (`usage`, `limits`, `alerts`, `sessions`, `ingest`, `session:<id>`), so pages refresh themselves. Global state (settings, live status, unread alerts, ingest progress) is in `stores/app.svelte.ts`; change settings with `updateSettings()`, which applies the change at once and rolls it back if the server refuses it.

The mock server is `src/lib/mock`. It is loaded only through a dynamic import, so it never sits in the main chunk. All views are aggregated from one list of synthetic requests, and `mock.test.ts` checks that the figures agree across endpoints; keep it that way when you add views.

## Adding to a page

Pages are in `src/pages` and registered in `src/App.svelte` (lazy loaded) and `src/lib/shell/nav.ts` (navigation and the export view the command palette offers on that page). The pages other than the dashboard are early views that already load their data; build on them rather than starting over. A page starts with `PageHeader`, keeps its filters in that header's single row, uses `Card` or `ChartCard` for each block, handles the loading, empty and error states, and shows the confidence of every money figure. Lay out for 360 px first; the shell switches to a drawer below 1024 px. Keep keyboard use complete (the command palette is Ctrl or Cmd+K), keep focus visible, and leave motion to the global reduced-motion rule in `global.css`.
