# Homebrew tap workflow

The files in this directory do not belong in the Kanjo repository's own automation. They are the template for the separate tap repository `Kyotu-Technology/homebrew-tap`, which is what makes `brew install kyotu-technology/tap/kanjo` work. GitHub does not run workflows stored here; the workflow only runs once it is copied to `.github/workflows/update-kanjo.yml` in the tap repository.

Each Kanjo release attaches a generated formula, `kanjo.rb`, which installs the prebuilt archives of that release for macOS and Linux on arm64 and x86_64, pinned to their SHA-256 checksums. The workflow `update-kanjo.yml` runs every day and on demand. It finds the latest release of `Kyotu-Technology/kanjo` (or the tag given when it is started by hand), downloads `kanjo.rb`, and checks with `gh attestation verify` that the file was built by `.github/workflows/release.yml` of the Kanjo repository from that tag on a GitHub-hosted runner. Only then does it write the file to `Formula/kanjo.rb`, and only when the content changed. Before the first Kanjo release it reports that there is nothing to do and succeeds.

The workflow needs no secret. It reads the public Kanjo release with the tap's own `GITHUB_TOKEN` and commits through the contents API with the same token, for which the job asks for `contents: write`. Nothing in the Kanjo repository can write to the tap, and nothing in the tap can write to Kanjo. A commit made with `GITHUB_TOKEN` does not start other workflows in the tap.

To set the tap up once: create the public repository `Kyotu-Technology/homebrew-tap`, add this README and `update-kanjo.yml` as `.github/workflows/update-kanjo.yml`, and make sure the organisation allows workflows to request write permissions. After a Kanjo release, start the workflow from the Actions tab or with `gh workflow run update-kanjo.yml --repo Kyotu-Technology/homebrew-tap` instead of waiting for the daily run, then check `brew install kyotu-technology/tap/kanjo` and `brew test kanjo` on a Mac.

GitHub disables scheduled workflows in a public repository after 60 days without activity in it. If no release has changed the formula for that long, the daily run stops until the workflow is enabled again in the Actions tab; starting it by hand after a release works in either case.
